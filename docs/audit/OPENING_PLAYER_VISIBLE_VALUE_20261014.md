# Gray Crown — プレイヤー可視の序盤改善・品質受入監査（2026-10-14）

## 判定: 実装候補、商用品質は未承認

以前の PR #77 は実際にプレイヤーから「住民が同じ、王都が変わらない、寄り道が退屈、全体が安っぽい」と拒否された。**矩形描画数・ファイル数・コード上の輪郭パターンを品質合格と扱わない。** この変更は不合格の美術 PR #77 から積まず、操作改善・初戦闘テストが入っている PR #76 から分岐した。本編と元のNPC/Spriteを上書きせず、規模ではなく体験の利点を証明する。

### 今回、プレイヤーに現れる違い

| 体験 | 変更前 | 変更後（候補） | 合格とする条件 |
|---|---|---|---|
| 西畑／小川の寄り道 | 両方を調べて農夫に戻らないと旅の携帯食が得られない | **どちらか片方の現地調査 → ボルへの報告** で既存の携帯食1個を受け取れる | 新規ゲームの通常操作で片方だけ寄って報告→村を出られる。行き帰りに無意味な2エリア強制往復がない |

### 制作意図

この改修は、「NPC数を増やす」「土地を2枚追加する」「短い回想を作る」を目的にしていない。既存の小さな判断が **操作 → 実際の世界側の反応 → 一度だけの報酬または自分で気づく戦術** へつながることを狙う。調べた場所を忘れる台詞、訪れていない場所の測量印、無理に褒める戦闘後の演出は不合格。

**まだ未解決:** 24×15の西畑と東小川の「歩き回ること自体が楽しいか」、住民32pxの顔・衣装・建物の安っぽさ。これらは今回のイベント分岐では直っていない。次の実プレイで面白くなければ、マップの広さ／配置／アート自体を縮小・再制作する。イベントをさらに足す口実にしない。

### 技術整合性（変更禁止事項）

- アルファの任命式、村北門、王都・古砦イベント、主役4人のキャラPNG、Story 00–19、Save schema 23、戦闘ダメージの係数や敵HPを変更しない。
- `ryune.outskirts.reward` は既存の一度きりの食料付与フラグ。新たな `ryune.outskirts.reported.fields` / `ryune.outskirts.reported.brook` は **見たものと伝えたものだけ** を追う。保存時は従来の `events.completed` へ書く。
- 両方同時の従来の報告は維持し、一次報告→追加報告の順序を問わない。追加報告にはアイテム・能力値・通行フラグを与えない。
- `openingWolfReaction` は既存の狼勝利イベントを **複製した一時的な会話配列** として描画するのみ。原本 `EVENT_DEFS` / 永続イベント / 4人のHP・MP / 報酬は変更しない。

### 実行済み確認（2026-10-14）

GitHubから取った**今回の実ソース**をV8で構文解析、Story/イベントエンジンの本物の条件・効果関数を最小限のUI代替下で実行した。

- **95件のイベントIDがすべて一意**、対象JavaScript全体に構文エラーなし。
- 西畑のみ／小川のみ／両方を先に見る／畑→川の順次報告／川→畑の順次報告、**5経路とも一度だけ携帯食を獲得**、いずれもStory `00_village` のまま。
- 実ピクセル描画を呼び出して **畑だけ4描画・川だけ3描画／未報告は0** の区別を確認（矩形数は品質指標ではない）。
- 実コンバットソースの `openingWolfReaction` で「無条件：従来の台詞／本当に庇った：カレン／足跡を調べた：マーガレット」を確認。必須会話の行数は増えない。
- 実 `CommercialUX.action` で狼は「向き合う」、レバーは「操作する」、小川は「調べる」の案内を返す。
