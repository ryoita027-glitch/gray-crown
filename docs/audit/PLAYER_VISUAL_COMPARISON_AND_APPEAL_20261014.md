# Gray Crown — 人が遊ぶ画面での旧版比較と住民魅力度審査（2026-10-14）

## 最優先の結論
**美術の完成承認は引き続き不可。** 同じ画面上で「前より人物が魅力的」「王都に生活や物語がある」と初見プレイヤーが感じられることを完成条件とする。
HTML/CSS/JS修正本数、PNGサイズ、NPC数、描画命令数、静的テストPASSを人間の魅力度の代わりにしない。

## 本当に撮影した画面と比較の限界
モデルの作業環境でChromiumを操作し、ライブラリ内の配布物
`GrayCrown_v21_整理済み_Play.zip` と
`Gray_Crown_v35_World_Scale_Grounding_Play.zip` をそれぞれ起動した。
同一のゲーム内座標と1280px/390px幅でリュネ村・王都を撮影した。
画面のマップ指定は**比較用の状態シード**であり、ストーリーを人力で進めた証拠ではない。
リュネの開始画面は通常のNew Game経路でも確認した。
これらのスクリーンショットは**前日の保存ZIP同士**の比較であり、
このPR HEADで撮影できたという意味では決してない。

### 人間目線の判定（旧v21 vs保存v35）
- **王都の印象：不合格。** 一目で構造が変わったと言えない。広い石舗装、直線配置の店面、離れたNPCが目立ち、実際に暮らす町の体温が伝わりにくい。
- **NPCの魅力：不合格。** 画面等倍では肩・眼・口・動作が弱く、誰が何をしているかを外観だけで察しにくい。主人公との描き込み密度の段差が大きい。
- **主人公の見分け：部分改善。** 4人の髪/服の違いは分かるが、それだけで一体感や町の美術品質が上がったとは言えない。
- **UI：要調整。** 黒い見出しやゲージが多い一方、ワールド中の人物の小ささを補えていない。プレイヤーの注意が人物でなく画面パーツに取られる。
- **客観的な満足度調査：実施していない。** 「プレイヤーの90%が改善を評価した」などの数字を作らない。

## 最新PR #80の重要な実修復
`assets/npc/featured_residents_v1.png`（9名×4方向）の旧GitHub blobは
幅288/高さ128のヘッダーだけ合っていたが、PNGのIDAT長／CRCが破綻していた。
正常にinflateすると**35960バイト**で、必要な **128×289=36992バイト**を満たさなかった。
ブラウザが画像ロードに失敗すると共通NPC描画へ戻るため、見た目の差が消える重大な原因になった可能性がある。

既存の色・32pxの4方向・9人の画素を可能な限り保持し、
**最後の4走査行のみ、足元の既存画素から復元した有効なPNG**へ差し替えた。
モデルの画像デコードで開けることを確認した。元画像とビット単位で同一とは言わない。
`tests/featured_resident_player_visual.test.js` は、全PNGチャンクCRC、IENDまでの正しい構造、
zlib全展開長と行フィルターを検査するよう変更。
これにより正常なPNG署名だけではテストを通過できない。

さらに`js/data/npcs.js`の9人の会話ポートレートを、
すべて同じ顔のテンプレートではなく各人のPNG描画へ接続。
スタンドアロンHTML版では`__GC_INLINE_ASSETS__`から参照するようにし、オフライン欠損を回避。
`tests/featured_resident_dialogue_portraits.test.js`に人物別マッピングとオフラインの検査を追加。

## なお魅力が不足している点
1. **顔の表情：未承認。** 32px素材の顔は眼や口の情報が数画素で、会話の感情と自然に連動する表情フレームがない。
2. **動き：未承認。** 修復した9人のPNGは4方向それぞれ1ポーズ。作業・会話・歩行の個別アニメーションは制作されていない。
3. **街：未承認。** 王都の建物正面デザインはこのPRで改修中だが、最新ゲームの実スクリーンショットで前後比較できていない。
4. **初見の楽しさ：未承認。** 話しかけたくなる住人の存在感、寄り道をする目的、王都の賑わいを初見プレイで確認できていない。
5. **配布確認：未承認。** 同一SHAのWindows/スマホ環境で旧SaveとPNG表示を検証していない。
