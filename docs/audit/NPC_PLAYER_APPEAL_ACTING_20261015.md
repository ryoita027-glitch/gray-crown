# Gray Crown — NPCの顔・頭身・役割別の演技を「遊ぶ人基準」で再設計 (2026-10-15)

## 結論
**候補実装。商品完成扱い禁止。** PR #82で変更した9人の48px顔原型は維持。
静止素材を上に動かすだけの擬似アニメではなく、各人物の手と道具、目元の表情を描き直した専用フレームをゲーム描画に接続した。
主人公4人の画像、衣装、戦闘表示、キャラ設定には一切変更なし。

## 9人: 48px×正面2つの「別作画」演技
`assets/npc/featured_resident_actions_v2.png` は幅432×高さ96px（9人×2フレーム）。
`featured_residents_v1.png` は四方向待機・会話ポートレート用として保持。
この2ファイルのピクセル画像は役割別の描画であり、単に「画像全体をずらす」処理ではない。

| 人物 | 演技の違い |
|---|---|
| エダ（パン屋） | パンを載せたトレーを持ち上げ、表情をやわらげる |
| ボル（農夫） | 汗を拭き、農具を握り直す |
| ナナ（老婆） | 杖を持ったまま手を上げ、穏やかにまばたく |
| 村長 | 台帳を開き直し、文字を目で追う |
| 王国使者 | 封筒を差し出し、次の命令を確かめる |
| レン（子ども） | 木剣を構え直す。足元は移動しない |
| 花売りの少女 | 客に花を差し出し、笑いかける |
| 新兵 | 槍を持つ手を直し、少し緊張したまま立つ |
| グランツ | 指示書を持ち直し、厳しい姿勢を保つ |

`OpeningWorldLife.workPhase` の0=待機、1=仕事動作A、3=仕事動作Bと同期。
近距離でのみ描画更新。移動を伴わない人物は足を滑らせない。
`prefers-reduced-motion` が有効なら動作フレームを出さない。アクション画像が欠落/読み込み失敗なら元の48px原画で表示する。
横・背面は既存の正しい向きを保持し、**専用演技が現状は正面だけ**という未完事項を隠さない。

## 37の共通素体: 色替えから性格表現へ
従来の名前ハッシュ任せの目・口パターンをやめ、37プロファイルに一人ずつ
`bright/gentle/weary/guarded/focused/curious/shy` の表情方針を指定。
眉の角度、瞳の縦幅・光、頬・口元に反映。
子どもの頭と胴を下げて成人からの年齢差をつけ、老人は少し低い重心にする。
**これは37人の個別48px原画を完成させたという意味ではない**。体格の共通部分が残る住民には再作画が必要。

## 実際のゲーム表示で特に重要な修正
以前の`OpeningWorldLife.villager`はPNGの上に大型四角いトレー等を描き足し、
`CapitalEnvironment.npcAccent`は綺麗に描いた服の前に四角い制服を被せていた。
48px素材が正しく読み込めたら二重描画を止める。素材読込失敗時の後方互換パスは維持。
`assets/`を再帰パッケージする既存リリースビルダーと単一HTMLビルダーは追加PNGを自動同梱する設計。

## 技術的検証と商品品質の区別
- PNG 432×96の2フレーム×9人が両方描画され、アルファ透過が存在し、GitHub blob SHAと作画したPNGのgit hashが一致することを確認。
- GitHubの実ソースをV8で実行し、9人の初動/後動/背面の合計36回のシート切替を検証。画像リクエストは最初の2回だけ。
- 既存テストと追加`tests/npc_player_appeal_acting.test.js`、`tests/generic_npc_face_foundation.test.js`でPNG CRC・復号、ゲーム描画、37人の割当と服の重ね描きを保護。
- **現行ブランチの通しプレイ・同一SHAのChromiumスクリーンショット・Windows/スマホ・配布単一HTMLの実起動・第三者による外見の魅力度は未実施。**
  古いビルドで差し替えた比較画面を完成証拠として流用しない。

## 初見プレイヤー基準の不合格条件
1. 名前と職業表示を隠した48px等倍でも、9人が「同じ顔の服替え」に見える。
2. 主要9人の作業姿が人間の行動に見えず、道具の浮きや腕の不自然さがある。
3. 一部の村人だけ出来が良く、町全体の人口の顔と体格差が不足する。
4. 主人公との画風密度差がまだ目立つ。
5. 実ゲームの正面以外で動かないことが作品の弱さになっている。
6. 会話・実際の初見ストーリーの面白さにつながっていない。
