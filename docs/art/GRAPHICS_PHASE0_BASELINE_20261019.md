## 4. 問題の切り分け

**現時点で支持される事実**
1. 上記のフィールド主系統は、X/Yに異なる拡大率を指定していない。頭潰れの真因を単純な画像伸縮と断定できない。
2. 元48px→表示44pxとカメラの小数倍率により、極小の目・髪・輪郭の画素が揺れたり判別しづらくなったりする可能性がある。実画面で検証する。
3. 実Idle画像の同条件目視ではマーガレットの髪に紫味が際立つ。銀白色の正式個性はそのままに、影、毛束密度、輪郭線、衣装、接地を4人並列で評価する。
4. CSSには過去の異なる戦闘サイズ規則が多層に残る。最終値だけで美術合格とせずブラウザの計算済みスタイルと実スクリーンショットで確認する。
5. 新しい部位別制作ツールはあるが、本番承認済みの部位別新キャラクターPNGは確認できない。

**未確定のまま残す点**
- 頭部の違和感が原画、切り出し、カメラ、縮小、重なりのどれから生じるか。
- マーガレットの浮き方の原因が色・顔・頭身・影・衣装のどれか。
- 狼など敵の表示不具合の現行HEAD再現。
- 人物と扉・家具・建物・背景との相対尺度。
- 4主人公のフィールド／会話／戦闘一致。PC・スマホの実視認性とFPS。
- 起動→村→古砦→戦闘→セーブ→ロードまでの同じSHAでの実機プレイ。
- 3D化が2Dの完成改善案を上回るか。方式は正式決定しない。

1. **tools/graphics_phase0_compare.html**：Chrome/Edge等でローカルに開く。同じチェックアウト内の主人公原PNG8枚を読む。4人・4方向・待機／歩行・44/48/60/64/72px・同背景・同接地を切替。通常倍率と4倍補助表示。誤寸法や読込失敗を表示。

3. **本資料**：比較対象SHA、確認済み事実、未確認、次工程を固定。

## 7. 次工程（Phase 1以降）

- Phase 1-A：描画の真因を確定。縦横比・切り出し・カメラをまず検証し、必要な部分だけ修正。
- Phase 1-B：カレンの顔、目・まぶた、前髪・側髪・後ろ髪を部位別に制作。既存デザインとの通常倍率A/B合格後に胴体・動作へ拡張。
- Phase 1-C：4人で頭身・顔・陰影・足元を共通化しつつ個性保持。マーガレットは銀白色・非対称・知的顔・縦線を保ちつつ紫影と情報密度を調整。
- Phase 2：NPCの主要人物と住民代表から統一し、色替え量産しない。
- Phase 3：リュネ村で扉・窓・家具・人物の尺度と生活感を固定し、王都ほかへ展開。
- Phase 4：統一ポートレートと会話UI。
- Phase 5：敵可視化、戦闘人物の存在感、アクション伝達、PC/スマホのUI。
- Phase 6：同一統合HEADで実プレイ検証。個別候補の過去ログを転用しない。

指示書第12章の評価はキャラの魅力・統一感・識別性・画面構成・通常倍率での視認性を各5点満点。**20/25以上かつ全項目4以上は暫定合格候補**に過ぎない。点数が足りても旧版より良く見えなければ却下。

**保護するもの：** 主人公の原型、NPC・マップ、移動／衝突、会話、イベント、戦闘、進行、セーブ/ロード、オフライン起動。元画像は残す。既存Draft PRを自動統合しない。2Dから3Dへの正式変更は比較するまで保留する。
