Gray Crown — Stability & Developer Tools v20

目的
v19系アーキテクチャ移行後の本編正常性を実プレイヤー操作基準で再検証し、同種の回帰を自動検出できるゲートと Developer Mode v1 を追加した。
新章・新マップ・新キャラクター等の本番コンテンツ追加は行っていない。

本編正常化
- Alpha 1.0 を Title → New Game → リュネ村 → 勇者任命 → 街道 → 灰牙狼戦 → 王都 → 任命式 → 白鹿亭 → 08_alpha_complete まで実Chromium操作で完走確認。
- Alpha途中で通常Saveし、ブラウザ実行状態を作り直してContinueし、同じMap/座標/Story Stateから復帰後にAlpha終点まで完走するE2Eを追加。
- Continue時に復帰Mapに対応するBGMへ同期する処理を追加。
- タイトル画面でContinue/New Gameボタンにフォーカスした状態のEnterと、document全体のEnter処理が競合しないよう修正。
- 通常Save/Loadを会話・戦闘・レベルアップ等の一時状態では拒否し、不完全なタイマー/UI状態を保存しないよう変更。
- 破損した通常SaveはBackup Saveから復旧できるよう検証を強化。
- Story Stateと完了イベント/訪問Map/撃破Symbolが矛盾する旧Saveを読み込む際、Alpha 1.0の既知マイルストーンに基づいて不足条件を補修。
- UIボタンのclick Eventオブジェクトがsave/loadのsilent引数として誤解釈されるバインドを、明示的なラッパー関数へ修正。

回帰防止
- Save schemaを20へ更新。
- clean runtimeのData/State Validationを起動時にも実行。
- Map/NPC/Object/Event/Transition/Treasure/Shortcut/Skill/Item/Battleの確実に検査可能な参照整合性をValidationへ追加。
- Map内NPC/Object重複、Event ID重複、存在しないMap/NPC/Object/Item/Skill/Shortcut/Event State参照、成立不能な同一Event complete/incomplete条件を検出。
- source object literal上でBattle/Item/Skill keyが重複し、JavaScriptが静かに上書きする事故を回帰テストで検出。
- MAP_FEATURESのShortcut IDを実定義と一致させた。
- JavaScript全ファイルsyntax check + Node regression + browser startup + Alpha 1.0 E2E + Developer E2Eを `npm run check` に統合。

Developer Mode v1
- F2で開閉。
- Runtime: Map ID、Player座標/向き、Story State、Chapter、Objective、Lv/HP/MP、Gold、BGM、直近Event、Save Schema、Developer taintを表示。
- Story Inspector: Eventごとに発生可否と各条件PASS/FAILを表示。
- Story State「安全適用」: Alpha 1.0の関連Event/Visited/Defeated状態を対象Stageへ正規化してから安全地点へ移動。
- Flag Inspector: compatibility flag / World switch / One-shot eventをtrue/false付きで一覧表示。互換Flag/World switchは変更可能。
- Map Warp: 任意MapへnearestSafeTileを使って移動。
- Event Launcher: 条件付き実行と強制実行。
- Battle Launcher: 任意Battleを直接起動。
- Player Debug: Lv/EXP/HP/MP/Gold/Item数量変更。
- Gameplay Options: Encounter ON/OFF、Invincible、Instant Victory、移動delay、Collision/NPC座標/Player座標/Map ID表示。
- Debug Snapshot: 通常Saveとは別localStorage keyへ最大20件保存/復元。
- Validation/LogをDeveloper Panel内で確認可能。
- Developerによる状態変更はDEV TAINTEDとなり、通常Saveへ上書きできない。
- raw Map Warp/forced Eventのような意図的にStory整合性を無視する操作はValidationで矛盾を可視化する。

Logging
- Error / Warning / Story Event / Map Transition / Battle Start-End / Save / Load / Developer操作をリングバッファへ記録。
- window error / unhandledrejectionを可能な範囲で捕捉。
